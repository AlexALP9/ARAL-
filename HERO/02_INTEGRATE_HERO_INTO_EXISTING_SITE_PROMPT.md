# Внедрение нового ARAL Hero в текущий сайт

## Задача
Внести новый Hero в существующий сайт репозитория AlexALP9/ARAL-.

Не создавать новый сайт с нуля. Работать с текущей реализацией и заменить только существующий первый экран, сохранив действующую архитектуру, каталог и маршрутизацию.

## Текущие файлы сайта
Основные файлы:
- index.html
- assets/style.css
- assets/app.js
- catalog.json
- media/production/
- .github/workflows/pages.yml

## Что нельзя ломать
Обязательно сохранить:
- загрузку catalog.json;
- каталог;
- карточки товаров;
- поиск;
- фильтры;
- сравнение до 4 товаров;
- маршруты #/, #/catalog, #/product/..., #/compare, #/brand, #/business, #/drivers, #/where, #/contacts;
- B2B/B2C-логику;
- GitHub Pages deploy;
- текущие данные в current/*;
- все файлы в media/production/*.

Не менять продуктовые данные и технические характеристики.

## Что заменить
В index.html заменить текущий блок section.hero на новый Hero в светлой premium automotive стилистике.

## Визуальная логика
Использовать:
- светлый фон;
- крупный H1 слева;
- короткий текст;
- две CTA;
- крупные реальные канистры ARAL справа;
- много воздуха;
- ARAL blue / white / dark navy;
- небольшой restrained yellow accent;
- современный clean automotive look.

Не копировать LIQUI MOLY буквально. Использовать его только как ориентир по:
- product focus;
- whitespace;
- крупной типографике;
- премиальной подаче;
- чистой композиции.

## Тексты
Eyebrow:
ARAL · ТЕХНОЛОГИИ ДЛЯ ДВИЖЕНИЯ

H1:
Масла ARAL для тех, кто выбирает точность.

Текст:
Моторные масла и технические жидкости для легкового и коммерческого транспорта. Подбор по проверенным характеристикам и официальным данным.

CTA:
1. Подобрать масло
2. Смотреть каталог

Поведение CTA:
- «Подобрать масло» → #/drivers
- «Смотреть каталог» → #/catalog

## Канистры
Использовать реальные изображения из media/production/.

Предпочтительно:
- ARAL-003_20634_4L.jpg
- ARAL-010_15DBCE_4L.jpg
- ARAL-011_160EC7_5L.jpg

Можно сделать композицию:
- ARAL-003 — главный объект;
- ARAL-010 — второй план;
- ARAL-011 — третий план.

Не изменять содержимое изображений:
- не менять этикетки;
- не менять упаковку;
- не менять логотипы;
- не менять цвет;
- не дорисовывать товар.

Разрешены только:
- масштаб;
- позиционирование;
- CSS transform;
- mask/clip;
- shadow;
- opacity;
- лёгкий blur для заднего плана.

## CSS
Добавить/обновить стили Hero в assets/style.css.

Требования:
- desktop 1440–1600;
- tablet 768–1024;
- mobile 390–430;
- fluid spacing;
- без горизонтального overflow;
- изображения не должны растягиваться;
- корректный object-fit;
- визуально крупный product focus;
- CTA хорошо читаются;
- focus-visible состояния обязательны.

## Motion
Реализовать лёгкий motion без тяжёлых библиотек.

Допустимо:
- CSS transitions;
- лёгкий entrance;
- stagger через CSS;
- минимальный parallax через существующий JS или небольшой vanilla JS.

Не подключать:
- Three.js;
- тяжёлые animation libraries;
- сторонние CDN без необходимости.

Обязательно добавить prefers-reduced-motion — отключить parallax/entrance и сохранить полностью доступный контент.

## Accessibility
- alt-тексты у канистр;
- нормальная heading hierarchy;
- CTA доступны с клавиатуры;
- цветовой контраст не ниже комфортного уровня;
- декоративные элементы aria-hidden=true.

## Проверка после внедрения
Проверить:
1. Главная открывается без JS-ошибок.
2. catalog.json загружается.
3. Все маршруты работают.
4. Поиск работает.
5. Фильтры работают.
6. Compare работает.
7. Product Detail работает.
8. B2B/B2C страницы работают.
9. Desktop/mobile не имеют overflow.
10. Все hero-изображения существуют.
11. GitHub Pages workflow проходит успешно.
12. Никакие файлы current/master/*, current/content/*, current/catalog/* не изменены.

## Финальный результат
Нужно получить новый Hero в текущем сайте, а не отдельную демо-страницу.
После внесения изменений показать:
- изменённые файлы;
- краткое описание;
- desktop/mobile поведение;
- подтверждение, что каталог и маршруты не сломаны.
