# ARAL — целевая архитектура публикации

## Уровни сайта

1. **UI shell**: `index.html`, `assets/style.css`, `assets/app.js`, `assets/editorial.js`. Единственная hash-навигация для пользователей, продуктов и утверждённых редакционных страниц.
2. **Catalog domain**: `catalog.json` — статическая опубликованная реляционная по структуре база: product → variants → image/SKU; отдельные `content` и `technical`. Стабильные идентификаторы `internal_id`, SKU. Поиск/фильтры/фасовки/сравнение работают в клиенте. Секретов и сервера на GitHub Pages нет.
3. **Approved editorial**: `src/pages` — оригиналы утверждённых HTML (одна V8 включает Компания и Интересное). Сборка публикует в `pages/` без изменения текстов и верстки, добавляя `<base href="../">` для изображений. Контент изолирован в same-origin frame, чтобы CSS/JS не конфликтовали со стабильной продуктовой витриной. Это сознательный компромисс: SPA-host с изолированными HTML-видами; не единый React-компонентный DOM.
4. **Media**: публичная продукция `media/production/`, утверждённые редакционные изображения `media/editorial/`, исторические копии `archive/`. Сборка проверяет, что пути находятся в публикуемой директории.
5. **Documents**: `docs/available.json`, `scripts/build_docs.py`; публиковать только разрешённые PDS/SDS.
6. **Delivery**: `.github/workflows/pages.yml`, валидатор каталога, копирование разрешённых ресурсов, deployment GitHub Pages при обновлении main.

## Ключевые маршруты

- `#/` — главная.
- `#/catalog`, `#/product/ARAL-...`, `#/compare` — основной каталог и сделки B2B/B2C.
- `#/company`, `#/drivers`, `#/partners`, `#/advantages`, `#/interesting`, `#/contacts` — утверждённые страницы.
- `#/products-design` — отдельная утверждённая редакция каталога 15, без подмены публичной JSON-базы.
- `#/where` — каналы покупки.

## Границы и будущая миграция

GitHub Pages обслуживает только статику; реальная CRUD-БД, заявки и CRM требуют отдельного backend. Не представлять файл JSON как SQL базу данных. Не дополнять отсутствующие цены, допуски или реквизиты. Для окончательной component-native SPA требуется покомпонентный перенос HTML и интерактивного JS с регрессией утверждённых страниц; пока сохранение изоляции обосновано предотвращением конфликтов.

## Контроль качества

`python3 scripts/validate_catalog.py`, `python3 scripts/build_editorial.py`, сборка workflow, проверка всех ссылок на редакционные медиа, E2E: hash navigation, mobile, search, SKU, compare, docs, формы и карта. Статус Pages проверять по отдельному успешному GitHub Actions run.
