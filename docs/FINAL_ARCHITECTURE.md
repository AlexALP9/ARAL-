# ARAL — итоговая архитектура и исправление интеграции

## Решение пользователя

**Собрать один сайт из семи существующих HTML-черновиков, а не редизайн.** Главный критерий — узнаваемый неизменённый облик и сохранённые функции каждого утверждённого источника.

## Публикуемая архитектура

```
index.html                 # Компания + Интересное из утверждённого V8
pages/
  products-r15.html        # Продукция, revision 15
  drivers-08.html          # Для водителей
  partners-11.html         # Для партнёров
  advantages-04.html       # Преимущества ARAL
  contacts-03.html         # Контакты
media/
  editorial/               # 33 оригинальных фото/изображения HTML
  production/              # 47 изображений фасовок/артикулов
src/pages/                 # Нетронутые исходники черновиков
catalog.json               # Сохранённый публичный JSON reference catalog
current/                   # MASTER, CONTENT, MEDIA, PDS-принятие
archive/                   # История проекта
.github/workflows/pages.yml
```

## Принципы интеграции

1. **Ни одной новой визуальной оболочки.** Стили HTML — часть оригинальных документов; никакой дополнительной надстройки с собственным HERO, меню или футером.
2. **Без iframe.** Полные страницы переходят друг в друга обычными ссылками; логотип возвращает на Компанию. Внутренние якоря, локальные интерактивные компоненты и исходный JS сохранены.
3. **V8 только для Компании и Интересного.** Пять других версий из V8 скрыты/недоступны через основной роутер; основное меню направляет на соответствующие более новые черновики.
4. **Продукция revision 15.** Внутренние хеш-маршруты карточек и сравнения сохранены; убран обработчик, блокировавший ссылки на другие разделы. Источник фотографий фасовок перенаправлен на локальные опубликованные изображения.
5. **Навигация единая по порядку**, но стилистика каждой шапки остаётся как в переданном HTML; не подменять одно меню другим без утверждения.
6. **Медиа по SHA.** Изображения вынесены из data URI; Git SHA-1 каждого из 33 редакционных blob совпадает с исходными байтами data URI пользовательских HTML. Исправлены первоначально неверные расширения 22 файлов V8.
7. **Документы и технические характеристики**: замороженный MASTER сохранён; отсутствующие допуски, цены и контакты не выдумываются, заблокированные PDS/SDS не активируются.

## Выбор архитектуры

Это **MPA / статический многостраничный сайт**, а не компонентный SPA. Такой способ сознательно выбран вместо ошибочной SPA-оболочки: независимые CSS-системы и скрипты шести автономных HTML при загрузке в общий DOM конфликтовали бы и изменяли отображение. Для текущего требования визуальной точности MPA корректнее и проще. Каталог revision 15 и V8 содержат собственный клиентский hash-router в своих документах.

## Разграничение данных

`catalog.json` — сохранённая независимая публикационная JSON-база, содержащая 17 продуктов и 47 SKU. HTML редакции 15 использует свой внутренний подтверждённый набор и интерфейс. Автоматическую синхронизацию между ними отдельно не объявлять завершённой. GitHub Pages не предоставляет API-бэкенд или реляционную СУБД.

## Проверки

CI: структуры HTML и меню; отсутствие iframe и отключённых пунктов навигации; разрешение ссылок редакционных изображений; 33 оригинальных image blobs; 47 product images и 17 продуктов; успешная загрузка артефакта GitHub Pages.

Браузерные проверки вручную: мобильное и десктопное отображение, раскрытие статей, временная шкала, фильтры, фасовки, сравнение, карта партнёров, поиск магазина, браузерные назад/вперёд. Эти проверки не выдаются за выполненные без фактического теста.
