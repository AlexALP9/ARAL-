# ARAL — архитектура сайта и реестр материалов

Дата систематизации: 2026-10-27. Основная ветка: `main`.

## Публичная структура

- `index.html`, `assets/app.js`, `assets/style.css` — текущий клиентский интерфейс на JavaScript с hash-маршрутизацией.
- `catalog.json` — опубликованная статическая база карточек: **17 продуктов и 47 SKU**. Данные читаются сайтом через fetch; GitHub Pages не предоставляет серверную СУБД.
- `current/catalog/ARAL_PUBLIC_CATALOG_v1.json` — контрольная публичная версия каталога.
- `current/master/` — продуктовые технические данные, не менять автоматически.
- `media/production/` — единый **публичный** каталог 47 изображений SKU.
- `docs/available.json` и `docs/pds`, `docs/sds` — только разрешённые к публикации документы.
- `.github/workflows/pages.yml` — сборка/проверка и публикация GitHub Pages.
- `archive/original-root-images/` — оригинальные изображения, ранее находившиеся в корне.
- `archive/site-before-integration/` — копия ранее опубликованного интерфейса, доступна для восстановления.

## Утверждённые источники и их приоритет

1. «Компания» и «Интересное»: V8; соответствующие экраны `view-company` и `view-interesting`.
2. «Продукция»: revision 15; 17 продуктов / 47 SKU, сравнение до четырёх.
3. «Для водителей»: черновик 08; «Для партнёров»: редакция 11.
4. «Преимущества ARAL»: редакция 04; «Контакты»: черновик 03.

**Ограничение:** шесть исходных HTML пользователя, включая V8 и revision 15, были предоставлены в чате, но не перенесены этим коммитом в репозиторий. Существующее приложение не следует считать полной интеграцией утверждённых семи страниц. Локальный совместимый предпросмотр создан отдельно и требует следующего этапа компонентной интеграции и регрессионных тестов.

## Правила контента

Не генерировать отсутствующие характеристики, цены, допуски, контакты, карту или изображения. Не поднимать документы PDS/SDS со статусом блокировки. Сохранять исходный состав 17 продуктов/47 SKU и не редактировать frozen MASTER без отдельного согласования. Указывать действительное состояние публикации, а не выдавать исходники за опубликованные страницы.

## Проверки

- Убедиться, что каждой `variants[].image` соответствует существующий файл в `media/production/`.
- Провести браузерные тесты прямого маршрута, refresh, Back/Forward, поиска, фасовок, сравнения и мобильной навигации.
- В GitHub Actions проверить успешный deployment и HTTPS, затем пройти все реальные страницы.
