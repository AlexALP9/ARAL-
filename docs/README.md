# PDF-паспорта на сайте ARAL — инструкция

## Что работает

На каждой карточке товара находится раздел «Документация» с отдельными ссылками **«Скачать паспорт продукта (PDS)»** и **«Скачать паспорт безопасности (SDS)»**. Ссылки появляются только если соответствующий проверенный PDF физически вошёл в опубликованный сайт. Отдельно показывается прямая ссылка на [поиск документов производителя](https://msdspds.aral.com/msdspds/msdspds.nsf/AralSearch?OpenForm&output=Full&&sitelang=EN).

Файл `docs/sources.json` содержит источники и разрешения публикации для 17 продуктов. Это **не замена** `current/master/ARAL_PRODUCT_MASTER_v1.2.json` и не источник технических характеристик.

## Как добавить уже полученный PDF

1. Найдите соответствующий **internal_id**, а не просто похожее название масла. Для идентифицированных продуктов пользуйтесь пользовательским соответствием SKU и паспортов, закреплённым в рабочей таблице.
2. В главном репозитории GitHub нажмите **Add file → Upload files** и загрузите исходный бинарный PDF в нужный путь:
   - `docs/pds/ARAL-XXX.pdf` — паспорт продукта (PDS);
   - `docs/sds/ARAL-XXX.pdf` — паспорт безопасности (SDS).
3. Сохраните изменения в ветку `main`. GitHub Pages workflow проверит каждый файл на PDF-заголовок, маркер конца и, где заранее известна контрольная сумма, — SHA-256. Если PDF отсутствует, workflow попробует скачать его по *прямому* URL производителя из `docs/sources.json`. **Домашняя страница/страница поиска не подходит для прямой загрузки.**
4. В готовом сайте GitHub Pages откройте `/docs/available.json`, затем карточку товара: кнопки должны вести к `/docs/pds/ARAL-XXX.pdf` и `/docs/sds/ARAL-XXX.pdf`. Загружайте исключительно свои утверждённые версии документов, не переименовывайте другой товар под нужный internal_id.
5. Отсутствующий PDF не создаёт неработающую кнопку. После добавления он появится при следующем успешном деплое. Неудавшееся скачивание с сайта производителя не блокирует сборку.

**Важно:** эти пути — инструкции для загрузки. Само наличие строки в данной таблице **не означает**, что бинарный PDF уже находится на GitHub. Через подключённый GitHub-коннектор текстовые файлы загружаются, но исходные PDF-байты из вложений чата не могут быть напрямую переданы в репозиторий. Их загрузка через GitHub UI / git / Codex Work требуется отдельно.

## Проверка и ограничения

- `.github/workflows/pages.yml` запускает `scripts/build_docs.py`, копирует доступные PDF и формирует `_site/docs/available.json` в Pages.
- Скрипт допускает скачивание только HTTPS с `aral-lubricants.de` и `msdspds.aral.com`. Повреждённые, недоступные или HTML-ответы не публикуются.
- `ARAL-008` и `ARAL-017` пока имеют `publication.pds=false`: не снимайте флаг без утверждённой новой версии MASTER. SDS — отдельные источники безопасности.
- `sds_status` в рабочей CSV означает наличие/принятие источника в учёте, но **не факт размещения PDF на сайте**.
- Не править автоматически frozen MASTER, технические значения, одобрения и пользовательские SKU ради кнопок.
- Для GitHub Pages URL сайта: `https://alexalp9.github.io/ARAL-/` (после успешной публикации).
