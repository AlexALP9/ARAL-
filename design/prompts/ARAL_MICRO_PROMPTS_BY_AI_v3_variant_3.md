Этот файл разбивает работу над сайтом ARAL на маленькие последовательные задачи. Каждый блок — отдельный промт. Не вставляйте целый раздел одному ИИ сразу.

# 0. Универсальный блок QUESTION FIRST

Добавляйте этот блок в начало любого промта, если сервис склонен сразу выполнять задачу без уточнений.

```text
РАБОТАЙ В РЕЖИМЕ QUESTION FIRST.

Перед выполнением:
1. Прочитай все приложенные файлы.
2. Не задавай вопросы, ответы на которые уже есть в ТЗ или приложенных материалах.
3. Сначала выведи:
   - Что уже известно.
   - Что отсутствует.
   - Какие противоречия найдены.
   - Какие решения нельзя принять без меня.

Если неизвестный ответ может повлиять на структуру, дизайн, данные, контент или техническую реализацию — сначала задай вопрос и дождись моего ответа.

Не более 7 вопросов за один заход.
Для каждого вопроса укажи:
- почему он важен;
- 2–3 варианта ответа, если это возможно;
- какой вариант ты рекомендуешь и почему.

Если вопрос не блокирует работу, пометь его как «Можно уточнить позже».

После моих ответов:
1. Кратко зафиксируй принятые решения.
2. Укажи, какие вопросы закрыты.
3. Только потом продолжай.

Не выдумывай отсутствующие данные.
Если данных нет — используй [НУЖНО УТОЧНИТЬ].
Если временно используешь допущение — явно помечай [ВРЕМЕННОЕ ПРЕДПОЛОЖЕНИЕ].
```

VS Code — не отдельный ИИ, а рабочая среда проекта и контроль изменений.

## VSCODE-01 — структура

Поддерживать:

```text
/docs
  MASTER_TZ_ARAL.md
  DECISION_LOG.md
  ADR.md
  CONTENT_RULES.md

/data
  ARAL_catalog_raw.xlsx
  ARAL_catalog_enriched.xlsx

/public/docs/pds

/src
/tests
/scripts
```

## VSCODE-02 — git workflow

Перед каждым крупным этапом:

```text
git status
git pull
создать отдельную feature branch
после изменений посмотреть git diff
запустить тесты
только потом commit
```

Примеры веток:

```text
feat/header-megamenu
feat/catalog
feat/product-detail
feat/compare
feat/b2b
feat/store-locator
chore/data-import
fix/accessibility
fix/performance
```

## VSCODE-03 — контроль каждого изменения Codex

```text
1. Открой git diff.
2. Проверь, не изменены ли несвязанные файлы.
3. Проверь, не появился ли hardcode товарных данных.
4. Проверь, не добавлены ли секреты.
5. Запусти lint/typecheck/tests/build.
6. Только после этого принимай изменение.
```

# 10. КОНТРОЛЬНЫЙ ПРОМТ ПЕРЕД СЛЕДУЮЩИМ ЭТАПОМ

```text
Перед переходом к следующему этапу проведи проверку.

1. Какие решения уже подтверждены мной?
2. Какие данные всё ещё неизвестны?
3. Есть ли противоречия между источниками?
4. Использовал ли ты где-нибудь предположение как факт?
5. Есть ли вопрос, который правильнее задать сейчас, чем исправлять потом?
6. Что именно будет считаться готовым результатом текущего этапа?

Если есть блокирующий вопрос — сначала задай его.
Не переходи дальше автоматически.
```
