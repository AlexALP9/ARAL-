# Техническое задание: монобрендовый сайт ARAL

**Версия:** 0.9 — мастер-ТЗ для продолжения дизайна в Figma и последующей разработки  
**Дата фиксации:** 07.10.2026  
**Статус:** живой документ. Зафиксированные решения отмечены как **[УТВЕРЖДЕНО]**, направления для проработки — **[РАБОЧЕЕ]**, отсутствующие данные — **[НУЖНО УТОЧНИТЬ]**.

---

## 1. Назначение документа

Этот документ — единая точка правды по проекту ARAL. Он нужен для:

1. отдельной ветки проектирования и дизайна в Figma;
2. последующей разработки сайта без повторного сбора требований;
3. наполнения каталога и карточек товаров;
4. постановки задач в Work mode на сбор номенклатуры, техлистов, терминологии и референсов;
5. сохранения гибкости проекта при росте каталога, добавлении контента, новых B2B-сценариев и новых функций.

### Базовый принцип
Не привязывать архитектуру сайта к текущему количеству товаров или к одному способу размещения. На старте ожидается **50+ товаров**, архитектура должна спокойно выдерживать **100+ товаров и дальнейшее расширение** без переделки основных страниц.

## 2. Концепция проекта

### 2.1. Что это за сайт
**[УТВЕРЖДЕНО]** Монобрендовый сайт ARAL, который представляет бренд, объясняет продукт, помогает подобрать подходящее масло и приводит пользователя к покупке через собственную инфраструктуру продаж и партнёров.

### 2.2. Аудитория
**[УТВЕРЖДЕНО]**
- B2B — ориентировочно **70%** приоритета.
- B2C — ориентировочно **30%**.

### 2.3. Два главных маршрута
**[УТВЕРЖДЕНО]** Верхнеуровневое разделение по логике Kärcher:

- **Для бизнеса**
- **Для автомобиля**

Формулировку «Коммерческое / Личное авто» не использовать как основную: «коммерческое» может восприниматься как коммерческий транспорт, а не B2B.

### 2.4. Главная задача B2B
Показать бренд ARAL как понятный, профессиональный и удобный продукт для:
- магазинов и сетей автозапчастей;
- СТО и автосервисов;
- оптовиков и дистрибьюторов;
- автопарков;
- коммерческого транспорта.

Сайт должен не только показывать товар, но и помогать партнёру продавать и применять ARAL: ассортимент, документация, обучение/материалы, рекомендации, контакт менеджера.

### 2.5. Главная задача B2C
Привести владельца автомобиля от понимания бренда к:
- выбору продукта;
- сравнению вариантов;
- подбору по параметрам;
- поиску точки покупки;
- покупке через доступный канал.

## 4. Архитектура сайта

### 4.1. Верхнеуровневая структура
Рекомендуемая структура, объединяющая раннюю и текущую концепции:

1. **Главная**
2. **О бренде**
3. **Продукты**
4. **Для автомобиля**
5. **Для бизнеса**
6. **Где купить**
7. **Сравнение** — сервисная страница, доступна через header и карточки
8. Служебные страницы: поиск, политика, cookies, 404 и т. п.

### 4.2. Что происходит с прежним разделом «Сотрудничество»
Ранее была зафиксирована отдельная страница «Сотрудничество».  
В новой архитектуре она не исчезает, а становится ключевым подразделом **«Для бизнеса»**.

Предлагаемая логика:

**Для бизнеса**
- Магазинам
- СТО / автосервисам
- Оптовикам / дистрибьюторам
- Автопаркам
- Коммерческому транспорту
- Сотрудничество
- Материалы и помощь в продажах
- Документы
- Связаться с менеджером

### 4.3. «Для автомобиля»
- Подобрать масло
- Подбор по параметрам
- Каталог
- Сравнение
- Допуски и спецификации
- Полезные материалы
- Где купить

### 4.4. Подбор масла
Ранее принято решение не делать полноценный подбор по автомобилю обязательной частью первого технического релиза.

Поэтому:
- **Figma:** интерфейс и место функции проектируются сразу;
- **Разработка v1:** допускается заглушка/переход на упрощённый подбор по параметрам;
- **v2:** подключение полноценного источника данных для подбора по автомобилю после выбора провайдера/API/базы.

Не имитировать работающий подбор без реальных данных.

## 6. Header и mega-menu

### 6.1. Референс
`02_STIHL_megamenu_reference.png`

### 6.2. Принцип
**[УТВЕРЖДЕНО ПО UX]**
Полноширинное mega-menu:
- открытие hover/click на desktop;
- `+` / caret меняется на активное состояние;
- панель разворачивается сверху вниз;
- ориентир анимации: 250–350 мс;
- при переключении пунктов panel shell может оставаться открытым, меняется содержимое;
- не делать каскад из маленьких вложенных dropdown.

### 6.3. Mobile
- fullscreen/large drawer;
- аккордеоны;
- никаких hover-only действий.

### 6.4. Header utility-зона
Функции, которые могут присутствовать:
- поиск;
- где купить;
- избранное;
- сравнение;
- кабинет;
- корзина.

**[НУЖНО УТОЧНИТЬ]** кабинет и корзина зависят от реального сценария продаж. Не проектировать сложный e-commerce без решения о покупке на сайте.

## 8. Карточка товара

Каждый товар должен иметь отдельную страницу.

### 8.1. Обязательные данные
- точное официальное название;
- серия;
- категория;
- вязкость;
- изображение;
- краткое описание;
- **Description** из актуального PDS — с аккуратным русским переводом;
- **Performance** — допуски/спецификации;
- tech sheet PDF;
- дата/версия техлиста;
- источник техлиста;
- фасовки — если подтверждены;
- CTA «Где купить» / «Запросить» / другой подтверждённый сценарий;
- кнопка «Добавить к сравнению».

### 8.2. Дополнительные поля
Если они есть в актуальном документе:
- Application;
- Advantages;
- Typical Characteristics;
- safety-related document links;
- рекомендации.

### 8.3. Правило переводов
Перевод должен:
- сохранять технический смысл;
- не добавлять несуществующие обещания;
- не превращать спецификации в маркетинговые лозунги;
- сохранять официальные обозначения SAE/API/ACEA/OEM без творческого пересказа.

## 13. Раздел «О бренде»

### Источник
Ранее было принято брать материал из отдельной листовки/материалов о бренде, без перегруза подробной хронологией.

Требования:
- кратко и доказуемо;
- бренд, происхождение, технологии, подход;

## 17. Анимации и интерактив

### 17.1. Интенсивность
Ранее пользователь оценивал желаемую насыщенность анимациями примерно **6–7/10, ближе к 6.5**.

### 17.2. Технологический принцип
- основа — 2D;
- небольшая часть 3D;
- 3D только там, где добавляет ценность;
- не строить сайт вокруг тяжёлого WebGL.

### 17.3. Одобренные механики
- smooth mega-menu;
- scroll storytelling;
- sticky/snap narrative blocks;
- teaser cards with depth;
- hover reveal;
- custom cursor на desktop;
- monochrome logo marquee;
- мягкие hover/transitions;
- сравнение с tray и состояниями.

### 17.4. Custom cursor
Использовать только на интерактивных зонах:
- «Открыть»
- «Подробнее»
- «Листать»
- «Смотреть»

На touch/mobile отключать.

### 17.5. Reduced motion
Поддержать `prefers-reduced-motion`: критичный контент должен оставаться доступным без анимации.
